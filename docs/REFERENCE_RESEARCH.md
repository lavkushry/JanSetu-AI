# JanSetu AI reference repository research

**Inspected:** 3 October 2026. **Purpose:** preserve the original CampusFix idea and assess the user's four OCR/vision references before incorporating their ideas into JanSetu. The user confirmed that “OCI” means **OCR: reading text from images**, not Oracle Cloud Infrastructure.

This is source inspection, not a runtime certification. Public default-branch commits were resolved through GitHub's API, their source archives were read without installing dependencies or executing repository code, and recommendations below are explicitly identified as design proposals. README descriptions and saved notebook outputs are author-provided evidence, not independent benchmark results. No third-party implementation, model weight, image, or dataset was copied into JanSetu.

## 2. CampusFix: preserve the journey, rebuild its foundations

### What the source implements

The manifest declares React, TypeScript, Vite, Tailwind, Motion, Lucide, Express, Firebase, and Google's GenAI SDK. This is an existing application prototype rather than a README-only concept; it does not implement JanSetu's selected Next.js/Go stack. [Package manifest](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/package.json).

Its view structure includes a student dashboard, report submission, tracking, personal reports, assistant, campus map, notifications, rewards, profile/settings, and administrative report, department, student, analytics, and heatmap screens. Views are selected through React context state. Reports carry category, priority, assignment, status, timeline, comments, and feedback. Those are useful starting points for JanSetu's operational case experience; the inspected structure does not supply a complete Reddit/X-style community and social graph. [Application views](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/src/App.tsx), [domain types](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/src/types/index.ts).

The report form implements file previews and camera capture, accepts an image as a data URL, offers editable AI suggestions, and lets a resident continue submitting when analysis fails. Its analysis request contains **title, description, and location only**. Uploaded image pixels are not sent to the AI route: photo evidence in this prototype is not evidence of OCR or image classification. [Report form](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/src/views/ReportIssueView.tsx), [API client](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/src/services/api.ts).

The Express analysis route attempts a GenAI call using the source's hard-coded `gemini-3.8-flash` identifier, JSON MIME output, and `JSON.parse`. That identifier is an observed configuration, not a verified model availability recommendation. It falls back to keyword-based category/priority rules. Duplicate suggestions use simple title/location string matching, and assistant context comes from a server-side in-memory report array. No runtime schema validation of the returned category/priority is present in this route. [AI and duplicate routes](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/server.ts#L1224).

### Important gaps

- **Split data context:** report CRUD/subscriptions use client Firestore, while Express AI/duplicate/chat logic reads its own seeded in-memory reports. There is no shared database lookup in those routes. New Firestore reports therefore do not automatically become the server array used for AI context. [Client database operations](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/src/services/firestoreDb.ts), [server store](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/server.ts).
- **Prototype identity controls:** Firestore rules allow unconditional reads/writes. The client database service compares plaintext password fields and accepts convenience overrides; context includes a convenience role switch. These controls are unsuitable foundations for JanSetu's role and evidence boundaries. [Rules](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/firestore.rules), [login implementation](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/src/services/firestoreDb.ts#L773), [application context](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/src/context/AppContext.tsx).
- **Voice fallback quality:** speech recognition uses the browser API with `en-US`. An unsupported browser receives placeholder transcript text; an empty apply-handler result has a predefined repair-description fallback. JanSetu must represent unavailable transcription explicitly, never insert fabricated report content. [Voice component](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/src/components/AudioVoiceRecordModal.tsx#L74).
- **Scalability and assets:** report reads/subscriptions fetch a whole collection and filter/sort in memory. Four bundled JPEGs are present without a separate asset provenance file in the snapshot. Rebuild query pagination and create or license JanSetu's own visual assets. [Database service](https://github.com/jsujansai/CampusFix--Ai/blob/34502d4c33285e9cdc942b1f377610705c9c8694/src/services/firestoreDb.ts), [image directory](https://github.com/jsujansai/CampusFix--Ai/tree/34502d4c33285e9cdc942b1f377610705c9c8694/src/assets/images).

**Design proposal:** retain fast reporting, editable suggestions, readable timelines, reopen/feedback flows, and staff queues. Add communities, follows, threaded discussion, and public receipts in JanSetu's own design system, backed by one authoritative case store.

## 3. RoadLens: useful pipeline design, conditional model capability

### What the source implements

`POST /api/analyze` validates an upload and executes quality analysis, conditional preprocessing, region/object detection, OCR, postprocessing, country-profile interpretation, and stage timing. Pydantic response models structure the output, and tests cover upload handling, profiles, schemas, detector interfaces, and OCR adapter substitution. [Pipeline route](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/backend/app/api/routes.py), [validation](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/backend/app/api/validation.py), [schemas](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/backend/app/schemas.py), [test directory](https://github.com/SamruddhiBhagwat24/roadlens-ai/tree/7045ae4516238b2246c9187d19871390f1810b45/tests).

The detector registry contains local-weight YOLO adapters and an HSV/contour fallback. OCR offers EasyOCR, Tesseract, and contour adapters. EasyOCR uses **English only**; an India profile does not establish Indian-script recognition. [Detector](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/backend/app/vision/detector.py), [OCR engines](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/backend/app/vision/ocr.py).

### Important gaps

- **Weights are absent from the checkout.** `models/` contains only `.gitkeep`; weights are excluded by `.gitignore`. EasyOCR requires `craft_mlt_25k.pth` and `english_g2.pth`, with downloads disabled. Its contour fallback emits `OCR_UNREADABLE`, not recognized characters. Deep-learning capability requires externally provisioned artifacts. [Model directory](https://github.com/SamruddhiBhagwat24/roadlens-ai/tree/7045ae4516238b2246c9187d19871390f1810b45/models), [ignored artifacts](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/.gitignore), [availability/fallback logic](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/backend/app/vision/ocr.py).
- **Packaged inference defaults to CPU.** Requirements pin `torch==2.10.0+cpu`; separate device-detection and training code accommodate accelerator environments. That is not evidence that the provided install uses AMD acceleration. [Requirements](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/backend/requirements.txt), [device detection](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/backend/app/performance/device.py), [training script](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/train_sign_detector_amd.py).
- **Semantic LLM enrichment is unfinished.** The optional Gemini method returns `None`; it does not make a provider request. [Interpreter](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/backend/app/intelligence/interpreter.py).
- **Evaluation is not independently reproduced here.** The README reports held-out test mAP@50 of 91.6% over 781 images/878 instances. The checkout does not contain the associated trained weight and full test dataset. Model tests skip inference when required files are unavailable. These numbers cannot be used as JanSetu's accuracy claim. [Reported results](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/README.md#L101), [model tests](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/tests/test_models.py).
- **Coordinate handling needs correction before adaptation.** Plate crops enlarge 2×, but EasyOCR boxes always divide by 4; Tesseract boxes do not undo enlargement. This static finding motivates tracking/inverting every transform before displaying regions; no runtime error rate was measured. [Crop resizing and box conversion](https://github.com/SamruddhiBhagwat24/roadlens-ai/blob/7045ae4516238b2246c9187d19871390f1810b45/backend/app/vision/ocr.py).

**Design proposal:** recreate the pipeline pattern and explainable region overlays. Do not treat road-sign/plate recognition as a trained pothole, water-leak, sanitation, or general civic-hazard detector. Those labels need their own validated models/data, or explicit abstention.

## 4. OCR challenge notebooks: experiments with visible failures

The repository contains only `ocr_challenge.ipynb` and `ocr_challenge2.ipynb`. Both attempt Florence-2-base OCR and then Tesseract on Tesseract's `eurotext.png` sample. Both saved Florence outputs contain an `AttributeError` involving `forced_bos_token_id`. This is evidence of an unsuccessful saved run, not proof that Florence-2 itself cannot perform OCR. [First notebook](https://github.com/tanishqjais123-ctrl/amd-ai-academy-challenges/blob/abc17686d77a1d04e1dd7c6a04a3dbe26c2dffe6/ocr_challenge.ipynb).

The second notebook adds CLAHE, denoising, adaptive thresholding, and Tesseract `--psm 6`. Saved outputs show readable sample text, a failed system-package install, and image-loading failures for the plate and speed-sign URL examples. Its successful “work-zone” example is again the general sample image, not field evidence of traffic-sign accuracy. Neither notebook provides a service, pinned deployment environment/model revision, trained weights, or a labeled benchmark. [Second notebook and saved outputs](https://github.com/tanishqjais123-ctrl/amd-ai-academy-challenges/blob/abc17686d77a1d04e1dd7c6a04a3dbe26c2dffe6/ocr_challenge2.ipynb).

**Design proposal:** use reproducible preprocessing experiments with known images, ground truth, and locked dependencies. Compare original and transformed input instead of assuming filters recover missing visual information. Treat Florence-2 as an optional candidate needing a working pinned integration and JanSetu evaluation.

## 5. BlackVision and ArmMind: ideas, not OCR implementations

BlackVision's README advertises persistent Chrome automation, agents, screenshots, memory, and integrations. The inspected runnable source is `demo.py`: timed console messages simulate Gmail, script generation, execution, and screenshot capture; SQLite log insertion is real. There is no image decoding, screenshot API, OCR adapter, model invocation, or browser operation in that demo. Listed dependencies do not establish that these features are implemented. [README](https://github.com/blackeface03/Blackvision-Aaenya-OS/blob/41f3b7c4e74c92d51e60e68907be05e690f8a2d3/README.md), [demo source](https://github.com/blackeface03/Blackvision-Aaenya-OS/blob/41f3b7c4e74c92d51e60e68907be05e690f8a2d3/demo.py), [dependencies](https://github.com/blackeface03/Blackvision-Aaenya-OS/blob/41f3b7c4e74c92d51e60e68907be05e690f8a2d3/requirements.txt).

ArmMind implements a Fireworks chat-completion call to `accounts/fireworks/models/gemma3-27b-it` using a static object/bin snapshot. It requests a JSON action plan with confidence/ambiguity notes and parses it with `json.loads`; execution prints a trace. Despite the README's phrase “validated action plan,” the source has no runtime schema, allowed-action, existing-object/bin, or step-sequence validation. OpenCV perception is described as earlier capstone work, not included in this repository. [README](https://github.com/Usama-Umar/armmind-amd-hackathon/blob/c36684ebe98b92a11cb8ec139e46d8370c0388f8/README.md), [planner source](https://github.com/Usama-Umar/armmind-amd-hackathon/blob/c36684ebe98b92a11cb8ec139e46d8370c0388f8/agent.py).

**Design proposal:** show real processing activity and retain structured suggestions with explicit assumptions. Validate every suggestion against JanSetu's schema and current department/case identifiers. Generated plans remain recommendations until an authorized workflow accepts them.

## 6. Recommended OCR and vision boundary for JanSetu

The following is a **new architecture proposal**, informed by the source findings above and aligned with the user's Go backend decision. Keep JanSetu's Go/PostgreSQL case workflow authoritative and implement Python/FastAPI media analysis behind provider-neutral contracts. The repository snapshots and factual findings above are independent of JanSetu's backend language choice.

| Boundary | Contract and behavior |
|---|---|
| Media preparation | Accept a private immutable media reference/hash; check ownership, byte and decoded-pixel limits, format/integrity, orientation, and image quality. Preserve original evidence separately from derived images. |
| OCR adapter | Return verbatim text spans, polygons in original-image coordinates, language/script, engine/model revision, recognition scores where supplied, and an explicit availability/readability status. Do not manufacture a score for engines that provide none. |
| Vision adapter | Return observed labels/regions and a clear distinction between detections and model interpretation. Abstain on unsupported civic categories or unusable images. |
| Interpretation adapter | Combine resident text with attributable OCR/detections into schema-validated suggestions. Preserve disagreement and uncertainty; verify suggested category/department IDs against the current catalog. Treat text in images as data, never instructions. |
| Processing job | Run asynchronously with idempotency, bounded retries/deadlines, resource and cost limits, stage telemetry, and explicit partial/failure states. Analysis failure does not prevent ordinary report submission. |
| Resident review | Allow crop/rotate/retake, edit extracted text, and confirm suggestions before attachment to a report. Keep model output distinct from the resident's statement and an agency's verified finding. |

**Evaluation candidates, not a winner:** Tesseract provides a CPU baseline and language data; EasyOCR provides scene-text boxes/text/scores but compatible language combinations must be selected; PaddleOCR merits evaluation for the pilot's required scripts; Florence-2 offers OCR/region tasks as an optional separate benchmark. Official language/model availability is not evidence of accuracy on JanSetu's photos or handwriting. [Tesseract project](https://github.com/tesseract-ocr/tesseract), [EasyOCR project](https://github.com/JaidedAI/EasyOCR), [PaddleOCR project](https://github.com/PaddlePaddle/PaddleOCR), [Microsoft Florence-2 model card](https://huggingface.co/microsoft/Florence-2-base).

Select the initial adapters using a labeled pilot corpus covering supported languages/mixed scripts, signs/notices/asset IDs, clutter, low light, blur, glare, rotation, tiny text, and negative images with no text or no supported hazard. Separate detector recall, OCR character/word error, correct normalized IDs, wrong confident suggestions, abstention, region alignment, latency, and cost. A model's own confidence is not a calibrated probability of truth.

Pin dependencies, model revisions and weight hashes; record required language packs and startup readiness. Benchmark CPU first, then choose an accelerator build only when measured throughput/latency/cost justifies it. No Oracle-cloud choice follows from the user's OCR request, and an AMD label in a reference does not require AMD hosting for JanSetu.

## 8. Reuse and release evidence

Source-level inspiration can proceed without copying the repositories. Before importing any implementation or assets, record project ownership/license, upstream package notices, weight provenance/terms, dataset/image rights, reproducible environment, and target-scenario evaluation. All five reference snapshots lack a declared project license; bundled assets and excluded weights require their own provenance rather than assumptions from visibility on GitHub.

For independently obtained upstream components, Tesseract, EasyOCR, and PaddleOCR publish Apache-2.0 licenses; the inspected Florence-2-base model publishes MIT; Ultralytics publishes AGPL-3.0. These are distinct upstream declarations, not licenses for the five reference projects or a full assessment of a proposed distribution. Choose the implementation and model licenses deliberately before integration. [Tesseract license](https://github.com/tesseract-ocr/tesseract/blob/main/LICENSE), [EasyOCR license](https://github.com/JaidedAI/EasyOCR/blob/master/LICENSE), [PaddleOCR license](https://github.com/PaddlePaddle/PaddleOCR/blob/main/LICENSE), [Florence-2 license](https://huggingface.co/microsoft/Florence-2-base/blob/main/LICENSE), [Ultralytics license](https://github.com/ultralytics/ultralytics/blob/main/LICENSE).

The practical outcome is a stronger specification: CampusFix supplies the original user journey, RoadLens supplies a modular pipeline reference, the notebooks supply small OCR experiments, and the other two projects supply activity-history and structured-planning ideas. None supplies a verified, licensed, complete Reddit/X-quality civic platform or a benchmark proving “best in every scenario.” JanSetu's quality must be established through its own implementation and scenario-based acceptance tests.
